AI Model Router / LLM Routing Rehberi

Güncelleme: 16 Eylül 2026 · 9 dk okuma
TL;DR: AI model router (LLM router), gelen bir isteği önceden tanımlı kurallara göre farklı modellere veya provider'lara yönlendiren bir katmandır. Cost routing, latency routing, capability routing ve failover routing olarak dört ana strateji vardır. Unichanl bu dört stratejiyi 127.0.0.1:20128 üzerinde yerel olarak çalıştırır; tek gateway key ile Anthropic, OpenAI, Google ve Bedrock arasında otomatik geçiş yapar.

AI model router nedir?

Model router, "hangi istek hangi modele gitmeli?" sorusunu bir uygulamanın iş mantığından ayıran ara katmandır. Uygulama kodu tek bir endpoint'e istek gönderir; router modelin, provider'ın ve versiyonun seçimini üstlenir. Böylece model değişikliği, fiyat optimizasyonu veya provider outage yönetimi kod değişikliği gerektirmez.

Neden LLM routing gerekli?

  1. Cost optimization: Basit özet için Haiku, kod için Sonnet, karmaşık planlama için Opus.
  2. Provider outage resilience: Anthropic 30 dakika down olduğunda Bedrock'a düş.
  3. Rate limit havuzlama: Aynı provider'a bağlı 3 anahtarı sırayla dene.
  4. Compliance: Belirli veri türlerini yalnızca AB/TR bölgesindeki modellere gönder.
  5. A/B testing: Trafiğin %10'unu yeni bir modele yönlendirip kalite karşılaştır.

Dört ana routing stratejisi

1. Cost routing

Tokenlere bakarak en ucuz uygun modeli seç. Örneğin 500 token altındaki basit istekler Haiku'ya, üstündekiler Sonnet'e gider.

{
  "strategy": "cost",
  "rules": [
    {"if": "tokens < 500", "route": "claude-haiku-4"},
    {"else": "claude-sonnet-4"}
  ]
}

2. Latency routing

En düşük gecikmeyi veren provider'ı seç. Gateway her provider için p95 latency ölçer ve dinamik olarak yönlendirir.

{
  "strategy": "latency",
  "candidates": ["anthropic-direct", "bedrock-us-east", "vertex-eu"],
  "measure_window_ms": 60000
}

3. Capability routing

İsteğin içeriğine göre yönlendir: vision içeriyorsa GPT-4o veya Gemini Pro Vision, sadece metin ise Claude Sonnet.

4. Failover routing

Öncelikli sıra: 1. tercih başarısız olursa 2., o da başarısızsa 3. Retry, timeout ve circuit breaker mantığıyla.

{
  "strategy": "failover",
  "chain": [
    {"provider": "anthropic", "model": "claude-sonnet-4", "timeout_ms": 30000},
    {"provider": "bedrock", "model": "claude-sonnet-4", "timeout_ms": 30000},
    {"provider": "vertex", "model": "claude-sonnet-4", "timeout_ms": 30000}
  ]
}

Unichanl ile routing örneği

Unichanl bu stratejileri dashboard'dan görsel olarak veya konfigürasyon dosyasıyla ayarlamaya izin verir. En basit haliyle sadece ANTHROPIC_BASE_URL'i gateway'e çevirmek yeter — Unichanl varsayılan failover routing'i devreye sokar.

# Terminal
export ANTHROPIC_BASE_URL=http://127.0.0.1:20128
export ANTHROPIC_API_KEY=sk-unichanl-YOUR_KEY

# Claude Code komutu — routing otomatik
claude "src/auth.ts dosyasını gözden geçir"

Programatik routing (SDK)

import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "http://127.0.0.1:20128",
  apiKey: process.env.UNICHANL_KEY
});

// x-unichanl-route header ile açık routing hint'i
const res = await client.messages.create({
  model: "claude-sonnet-4",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Refactor this function..." }]
}, {
  headers: { "x-unichanl-route": "failover:anthropic,bedrock,vertex" }
});

Routing metrikleri

Bir router'ın etkinliğini üç metrikle ölçün:

  • Effective cost / 1K token: Router açık vs kapalı fiyat farkı.
  • p95 latency: İsteklerin %95'i kaç ms altında yanıt aldı.
  • Availability: Router sayesinde ne kadar outage maskelendi.

Router vs Gateway vs Proxy

KavramAmaçÖrnek
RouterHangi model / provider?Unichanl, LiteLLM router modülü
GatewayAğ giriş noktası + policyUnichanl, Portkey
ProxyTrafik yönlendirmeOpenRouter, Helicone

Modern gateway'ler (Unichanl gibi) bu üç rolü tek üründe birleştirir.

Yaygın hatalar

  • Sadece cost routing kullanıp kaliteyi göz ardı etmek — küçük modele düşen zor istekler kullanıcı memnuniyetsizliği yaratır.
  • Failover chain'de farklı model aileleri koymak — Claude ile GPT'nin tone/format farkı beklenmedik davranış üretir.
  • Circuit breaker olmadan retry — aşağı düşen provider'a sonsuz retry, latency'yi patlatır.
